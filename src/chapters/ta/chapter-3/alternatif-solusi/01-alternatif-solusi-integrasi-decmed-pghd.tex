\subsection{Alternatif Arsitektur Pengumpulan dan Pipeline PGHD-DecMed}\label{alternatif-arsitektur-pipeline-pghd}

Berdasarkan analisis permasalahan di atas, terdapat beberapa arsitektur yang dipertimbangkan.

Pengumpulan data 

\subsubsection{Wearable Device}

Data PGHD bisa diambil dari wearable device seperti smartwatch ataupun IoT device lainnya.
Terdapat beberapa pertimbangan terkait keterlibatan dan integrasi wearable device.

\begin{enumerate}
    \item Hanya menggunakan sensor bawaan Android (tanpa wearable).
    \item Mengintegrasikan data dari wearable fisik ke Android.
    \item Mensimulasikan wearable via BLE (tanpa perangkat fisik).
\end{enumerate}

Mekanisme yang dipilih adalah data dari sensor di wearable devices akan dikirim ke perangkat Android, di mana API HealthConnect pada perangkat Android akan mengumpulkan seluruh data tersebut.
Implementasi ini dipilih agar kelengkapan dan kekayaan data dapat terjamin. % TODO: justifikasi dari referensi

\subsubsection{Aliran Data PGHD}

Terdapat tiga alternatif mekanisme pengummpulan dan pengiriman data yang dapat dipertimbangkan.

\begin{enumerate}
    \item Data raw dikirim langsung ke sistem DecMed
    \item Data diagregasi/diringkas di mobile sebelum dikirim ke DecMed
    \item Data raw disimpan lokal, hanya agregat/ringkasan yang dikirim ke DecMed
\end{enumerate}

Mekanisme yang dipilih adalah data raw disimpan di storage lokal dan dikirim dalam \textit{batch} ke DecMed tanpa agregasi di sisi klien pasien.
Pilihan ini memberikan nilai klinis yang lebih tinggi karena data asli tetap tersedia di ekosistem DecMed dan data asli dapat diakses oleh tenaga kesehatan tanpa kehilangan informasi apapun. % TODO: justifikasi referensi

\subsubsection{Trigger Pengiriman Data}

Terdapat dua mekanisme kapan pengiriman data dilakukan, yaitu \textit{time-based periodic} atau \textit{event-based periodic}.
Pada pengiriman berdasarkan \textit{time-based periodic}, data dikirim setiap interval waktu tetap, sementara pada \textit{event-based periodic}, pengiriman dipicu oleh peristiwa klinis tertentu, misalnya ketika detak jantung tiba-tiba naik drastis atau anomali terjadi.

Mekanisme yang dipilih adalah pengiriman batch berbasis interval waktu (\textit{time-based periodic batching}).
Pengiriman berbasis waktu memberikan prediktabilitas konsumsi baterai dan jaringan yang lebih baik dibanding \textit{event-based trigger}.
Selain itu, mekanisme event-based trigger juga rentan terhadap error pada perangkat ataupun anomali yang disebabkan faktor eksternal lainnya. % TODO: justifikasi referensi

Durasi yang digunakan untuk mengirimkan data dari klien ke sistem DecMed adalah setiap 15 menit sekali seperti rekomendasi Google HealthConnect API \parencite{android_hc_write}.
