\subsubsection{Pengumpulan Data dari Sumber PGHD}

Client pasien mengumpulkan PGHD dari beberapa sumber data seperti yang sudah dipilih pada Subbab~\ref{alternatif-sumber-data}. 
Sumber pertama adalah API sistem operasi untuk data \textit{wellness}, \textit{fitness}, dan \textit{activity}. 
API ini digunakan sebagai lapisan interoperabilitas antara aplikasi pasien, aplikasi kesehatan eksternal, dan perangkat \textit{wearable}. 
Sumber kedua adalah sensor internal perangkat pasien. 
Sumber ketiga adalah input manual yang diberikan langsung oleh pasien melalui antarmuka aplikasi.

Data dari seluruh sumber tersebut dinormalisasi menjadi struktur PGHD lokal pada Tabel~\ref{tab:field-pghd-raw-local}. 
Ketika data akan dikirim, \textit{record} lokal dibentuk menjadi \textit{batch} sesuai struktur pada Tabel~\ref{tab:field-batch-json-pghd}, Tabel~\ref{tab:field-datagroup-json-pghd}, dan Tabel~\ref{tab:field-datapoints-json-pghd}.

\subsubsection{Frekuensi Pengambilan dan Pengiriman Data}

Frekuensi pengambilan data dari setiap sumber dirancang mengikuti karakteristik sumber data dan kebutuhan ketersediaan sistem seperti yang sudah dijelaskan dan dipilih pada Subbab~\ref{alternatif-pengolahan-pghd}. 
Data dapat diambil per satuan waktu atau secara periodik atau sampai ukuran data mencapai batasan ukuran tertentu. 
Data yang telah terkumpul tidak langsung dikirim per \textit{record}, tetapi disimpan secara lokal dan dibentuk menjadi batch sebelum dikirim. 
Pemicu pembentukan atau pengiriman batch dijelaskan pada Subbab~\ref{mekanisme-pengumpulan-pghd} dan Subbab~\ref{subsubsec:pengiriman-pghd}.

\subsubsection{Penyimpanan Lokal}

\textit{Client} pasien menyimpan PGHD pada penyimpanan lokal sebelum data dikirim ke sistem. 
Penyimpanan lokal terdiri atas \textit{record} PGHD yang belum masuk \textit{batch}, envelope batch PGHD, dan \textit{data point batch}. 
Struktur data lokal dijelaskan pada Subbab~\ref{rancangan-solusi-format-data-lokal}. 
Mekanisme ini memastikan data tidak hilang ketika perangkat pasien berada dalam ko  ndisi offline.

\subsubsection{Proxy Layer dan Smart Contract}

Proxy Layer berperan sebagai \textit{middleware} yang memproses permintaan dari \textit{client} pasien dan \textit{client} tenaga kesehatan. 
Untuk PGHD, \textit{proxy} menerima batch terenkripsi, memverifikasi hash dan tanda tangan digital, menyimpan \textit{ciphertext} ke penyimpanan \textit{off-chain}, mencatat metadata ke \textit{smart contract}, serta menyediakan artefak \textit{proxy re-encryption} untuk tenaga kesehatan yang memiliki akses aktif untuk mendekripsi PGHD nantinya.

\textit{Smart contract} di IOTA menyimpan metadata PGHD untuk setiap entri mengikuti format pada Tabel~\ref{tab:iota-pghd-metadata}. 
Metadata tambahan seperti \textit{identifier} batch, \textit{key} dan \textit{nonce} terenkripsi, \texttt{capsule}, dan \textit{digital signature} diserialisasi mengikuti Tabel~\ref{tab:iota-pghd-serialized-metadata}. 
\textit{Smart contract} juga menyimpan informasi akses PGHD dan status validasi data.
