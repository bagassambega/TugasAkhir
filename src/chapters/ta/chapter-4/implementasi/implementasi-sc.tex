\subsection{Implementasi \textit{Smart Contract}}

 \textit{Smart contract} DecMed-PGHD diimplementasikan menggunakan bahasa pemrograman Move pada jaringan IOTA\@. 
 Implementasi \textit{smart contract} tetap menggunakan \textit{package} \texttt{decmed}, tetapi \textit{package} tersebut diperluas dengan mekanisme PGHD\@. 
 Perluasan tersebut meliputi penyimpanan \textit{public key} dan pengiriman data PGHD pasien ke IPFS, metadata PGHD, status validasi PGHD, akses \texttt{READ\_PGHD}, dan fungsi invalidasi PGHD\@.

\textit{Package} \texttt{decmed} dibagi menjadi beberapa \textit{module}. 
Daftar \textit{module} sistem DecMed-PGHD secara keseluruhan dapat dilihat pada Tabel~\ref{tab:lampiran-sc-modules-pghd} di Lampiran~\ref{app:implementasi-smart-contract}. 
Secara garis besar, \textit{package} \texttt{decmed} terdiri atas lima \textit{module} utama dan \textit{module} struktur data serta enum. 
\textit{Module} tersebut adalah \texttt{decmed::patient}, \texttt{decmed::hospital\_personnel}, \texttt{decmed::admin}, \texttt{decmed::proxy}, dan \texttt{decmed::shared}.

Diagram kelas pada \textit{smart contract} IOTA dapat dilihat pada Gambar~\ref{fig:diagram-modul-iota-pghd}.

\subsubsection{\textit{Module} \texttt{decmed::patient}}\label{subsubsec:sc-module-patient}

\textit{Module} \texttt{decmed::patient} berisi \textit{method} yang dapat dieksekusi oleh pasien. 
Pada implementasi DecMed-PGHD, \textit{module} ini menangani pendaftaran pasien, pembacaan informasi akun pasien, pembaruan metadata administratif pasien, pemberian akses kepada personel fasyankes, pencabutan akses, dan publikasi \textit{public key} PGHD pasien. 
Daftar \textit{method} yang diimplementasikan pada \textit{module} ini dapat dilihat pada Tabel~\ref{tab:lampiran-sc-method-patient}.

% Fungsi \texttt{create\_access} menjadi bagian penting karena fungsi ini membedakan akses RME biasa dan akses PGHD\@. Apabila metadata akses yang dikirim memiliki panjang satu elemen dan penerimanya adalah tenaga medis, \textit{smart contract} membentuk akses baca PGHD dengan tipe data \texttt{Pghd}. Apabila metadata memiliki dua elemen, \textit{smart contract} membentuk akses baca dan update untuk \textit{medical record}. Dengan pemisahan ini, pasien dapat memberikan akses PGHD tanpa harus memberikan akses update \textit{medical record}.

\subsubsection{\textit{Module} \texttt{decmed::hospital\_personnel}}\label{subsubsec:sc-module-hospital-personnel}

\textit{Module} \texttt{decmed::hospital\_personnel} berisi \textit{method} yang digunakan oleh admin rumah sakit, tenaga administratif, dan tenaga medis. 
\textit{Module} ini menangani aktivasi akun personel fasyankes, pembuatan \textit{activation key}, pembaruan metadata administratif, pembacaan daftar akses yang diterima dari pasien, serta pembersihan akses yang sudah kedaluwarsa. 
Daftar \textit{method} pada \textit{module} ini dapat dilihat pada Tabel~\ref{tab:lampiran-sc-method-hospital-personnel}.

% Dalam konteks PGHD, \textit{module} ini tidak menyimpan payload PGHD, tetapi menyimpan dan menyediakan data akun personel fasyankes yang akan menerima akses dari pasien. Akses yang sudah diberikan pasien kemudian digunakan oleh PRE dan \textit{smart contract} untuk memverifikasi apakah tenaga kesehatan masih memiliki capability yang aktif.

\subsubsection{\textit{Module} \texttt{decmed::proxy}}\label{subsubsec:sc-module-proxy}

\textit{Module} \texttt{decmed::proxy} berisi \textit{method} yang dipanggil oleh PRE\@. 
Daftar \textit{method} pada \textit{module} ini dapat dilihat pada Tabel~\ref{tab:lampiran-sc-method-proxy}. 
\textit{Module} ini menjadi menghubungkan antara PRE dan \textit{smart contract} karena PRE menggunakan \textit{module} ini untuk membuat capability \textit{proxy}, membaca data administratif dan \textit{medical record} sesuai akses, menyimpan metadata PGHD, membaca daftar metadata PGHD, membaca detail metadata PGHD, dan menginvalidasi metadata PGHD\@.

Metadata PGHD disimpan dalam struktur \texttt{PatientPghdMetadata}. 
Struktur tersebut menyimpan referensi dan metadata yang diperlukan untuk verifikasi \textit{provenance} dan integritas. 
\textit{Payload} PGHD terenkripsi disimpan pada IPFS, sedangkan \textit{smart contract} menyimpan CID dan hash \textit{ciphertext} untuk keperluan integritas.

\begin{lstlisting}[caption={Struktur Metadata PGHD pada \textit{smart contract}}, label={lst:patient-pghd-metadata-struct}, float=htb]
public struct PatientPghdMetadata has copy, drop, store {
    index: u64,
    cid: String,
    h_cipher: String,
    metadata: String,
    status: u8,
    failure_reason: String,
    timestamp: u64,
}
\end{lstlisting}

Setiap pasien memiliki objek \texttt{PatientPghdStore} yang berisi daftar \texttt{PatientPghdMetadata}.
Daftar objek IOTA yang berkaitan dengan PGHD, akses, dan pasien dapat dilihat pada Tabel~\ref{tab:lampiran-object-iota-pghd}.

\begin{lstlisting}[caption={Struktur penyimpanan metadata PGHD per pasien pada smart contract}, label={lst:patient-pghd-store-struct}, float=htb]
public struct PatientPghdStore has key {
    id: UID,
    patient_id: String,
    metadata: TableVec<PatientPghdMetadata>,
}
\end{lstlisting}

Nilai \texttt{status} digunakan untuk membedakan data valid dan invalid. 
Pada saat metadata PGHD baru dibuat, status bernilai \texttt{0}. 
Jika data terbukti rusak atau tidak sah, PRE atau tenaga kesehatan dapat menginvalidasi data tersebut sehingga status berubah menjadi \texttt{1} dan \texttt{failure\_reason} diisi dengan alasan invalidasi.

Validasi akses PGHD dilakukan melalui fungsi \texttt{assert\_pghd\_read\_access}. 
\textit{Smart contract} memeriksa apakah \textit{patient address} dan \textit{hospital personnel address} terdaftar, apakah akses baca terhadap pasien tersedia pada akun tenaga kesehatan, apakah tipe akses mengandung \texttt{Pghd}, dan apakah waktu akses belum kedaluwarsa. 
Jika akses kedaluwarsa, \textit{smart contract} menghapus akses tersebut dari \textit{map} akses tenaga kesehatan dan mengembalikan \textit{error} \texttt{EAccessExpired}.

\subsubsection{\textit{Module} \texttt{decmed::std\_enum\_*}}\label{subsubsec:sc-module-std-enum}

Tanda \texttt{*} menandakan terdapat beberapa \textit{module} yang diawali dengan nama \texttt{decmed::std\_enum\_}. 
\textit{Module} ini mendefinisikan enum seperti \textit{role} personel fasyankes, tipe akses, dan tipe data akses. 
Daftar enum \textit{module} dan \textit{method}-nya dapat dilihat pada Tabel~\ref{tab:lampiran-sc-method-std-enum}.

Enum yang terkait dengan PGHD adalah \texttt{decmed::std\_enum\_hospital\_personnel\_access\_data\_type}. 
Enum ini diperluas dengan nilai \texttt{Pghd} sehingga \textit{capability} akses dapat membedakan akses administratif, \textit{medical record}, dan PGHD\@.

\subsubsection{\textit{Module} \texttt{decmed::std\_struct\_*}}\label{subsubsec:sc-module-std-struct}

Tanda \texttt{*} menandakan terdapat beberapa \textit{module} yang diawali dengan nama \texttt{decmed::std\_struct\_}. 
\textit{Module}-\textit{module} tersebut merepresentasikan struktur data dari objek atau nilai yang disimpan pada IOTA, seperti akun pasien, akun personel fasyankes, metadata rumah sakit, metadata \textit{medical record}, metadata PGHD, \textit{access log} pasien, dan \textit{capability} akses personel fasyankes. 
Daftar struktur dan \textit{method}-nya dapat dilihat pada Tabel~\ref{tab:lampiran-sc-method-std-struct}.

Struktur untuk mekanisme kontrol akses adalah \texttt{HospitalPersonnelAccessData} pada \textit{module} \texttt{decmed::std\_struct\_hospital\_personnel\_access\_data}. 
Struktur ini merupakan bentuk \textit{capability} pada mekanisme CapBAC\@. 
Atribut \texttt{access\_data\_types} menentukan bagian data yang dapat diakses, \texttt{exp} menentukan waktu kedaluwarsa, \texttt{metadata} menyimpan material akses terenkripsi, dan \texttt{medical\_metadata\_index} digunakan untuk akses update \textit{medical record}.

\begin{lstlisting}[caption={Struktur data capability akses personel fasyankes}, label={lst:hospital-personnel-access-data-struct}, float=htb]
public struct HospitalPersonnelAccessData has copy, drop, store {
    access_data_types: vector<HospitalPersonnelAccessDataType>,
    exp: u64,
    metadata: String,
    medical_metadata_index: Option<u64>,
}

public enum HospitalPersonnelAccessDataType has copy, drop, store {
    Administrative,
    Medical,
    Pghd,
}
\end{lstlisting}
